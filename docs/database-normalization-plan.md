# Database Normalization Plan for DocAlert

## Current Model Structure

The application uses a normalized database schema with the following tables:

### 1. Users and Roles
```sql
CREATE TABLE app_user (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    email TEXT NOT NULL UNIQUE,
    password TEXT NOT NULL,
    user_type TEXT NOT NULL -- CLIENT or ADMIN
);

CREATE TABLE responsible_person (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    department TEXT DEFAULT 'N/A',
    position TEXT DEFAULT 'N/A',
    app_user_id BIGINT REFERENCES app_user(id)
);

CREATE TABLE document_types (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    name TEXT NOT NULL
);

CREATE TABLE document_statuses (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    name TEXT NOT NULL
);

CREATE TABLE vehicle_inspection_periods (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    description TEXT NOT NULL,
    days_until_renewal INTEGER NOT NULL
);

CREATE TABLE locations (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE resource_types (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE document_files (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    name TEXT DEFAULT 'N/A',
    number TEXT DEFAULT 'N/A',
    renewal_date DATE,
    renewal_period INTEGER,
    service_provider TEXT DEFAULT 'N/A',
    arhiva BOOLEAN,
    document_type_id BIGINT REFERENCES document_types(id),
    location_id BIGINT REFERENCES locations(id),
    resource_type_id BIGINT REFERENCES resource_types(id),
    responsible_person_id BIGINT REFERENCES responsible_person(id),
    status_id BIGINT REFERENCES document_statuses(id),
    vehicle_inspection_period_id BIGINT REFERENCES vehicle_inspection_periods(id),
    created_by BIGINT REFERENCES app_user(id)
);
```
